# 项目、研读与框架（M01／M02／M05）

## 项目约定

先核对研究对象与问题、资料截止日、项目及 Obsidian 主库位置、现有三份文件、附件位置、本轮输出方式和保护项。已有信息直接沿用，缺什么补什么，不强制填表。

正文和资料底稿优先为项目内 Markdown，数据为可编辑工作簿。项目不在已知主库内时提醒并给出可行位置；新建或迁移按用户授权及库规则执行，不自动修改 Obsidian 配置。主库未知时不猜测。

## 项目目录参考

以下是可按需采用的结构，不是必须一次建立的目录清单。

```text
项目文件夹/
├─ 正文初稿.md                ← 判断、分析与结论
├─ 资料底稿.md                ← 原文、证据与定位
├─ 数据底稿.xlsx              ← 原数、公式及可编辑图表
└─ support/                   ← 本项目专属，不跨项目混放
   ├─ 来源.md                 ← 渠道、日期、原始链接、文件对应关系
   ├─ 原始资料/               ← PDF、公告、数据库原始导出
   ├─ 证据截图/               ← 完整原页、必要裁切图
   └─ 正文图表/               ← 展示图与可编辑来源；Excel 图源仍在工作簿
```

- 按用途创建，不预建空目录或空 Excel。若项目已有 README 或导航，在其中登记入口即可，不重复制造文件。
- 库要求集中附件时，上述附件放“附件／项目名称”的等效位置，工作簿也遵守实际路径规则；导航记录真实位置。用户明确指定位置优先，并遵守权限。
- 原始文件保留原名；简称在索引登记。截图名能识别来源和原页或主题，新版加日期／版本，不覆盖旧图。裁切展示图与完整原页分别标明。
- 同一截图在外部只存一份、多处引用；数据截图还须嵌入 Excel。只贴文件名或网址不算图片留证。
- 沿用已有附件位置，不自动搬迁、重命名或删除。获准迁移时核对目标、更新受影响引用并检查图片与工作簿定位。
- 来源登记可复用；不同时建立内容重复的来源清单、登记表和索引。

## 研读与搜集

1. 先清点材料：全名、简称、发布者、日期、版本、类型、本地位置、原始链接和用途。按实际需要记录主体、可用数据和证据位置。
2. 先理解全局和关键问题，再梳理主体、事件及关系，最后核对定义与口径。事件日期、披露日期、报告期和核验日期分开。
3. 输出“关键发现—待解释问题—可用证据与数据—具体缺口”。初步研读不必建齐所有正式底稿，更不预先锁定论证框架。
4. 按缺口查原始披露、政策、行业资料或数据库，不只依赖新闻。使用适用的检索工具；如需联网而现有规则未授权，先处理本地材料并明确所需检索范围。
5. 参考报告记录可借鉴的章节逻辑、证据安排和图表表达，不把其主题和结论移植过来。正式留证按资料证据规范执行。

## 框架设计

以材料支持的研究问题确定主线；为各节写清“回答什么—依据什么—如何通向下一节”。检查证据空节点、背景过重及分析重复。只有数据重复但分析用途不同时，可以复用并说明用途。

| 研究类型 | 可选问题方向，不是固定目录 |
|---|---|
| 事件／案例 | 背景、行动主体、工具、作用渠道、结果与适用边界 |
| 行业深度 | 需求供给、竞争、技术、周期、政策与关键变量 |
| 公司深度 | 商业模式、业务结构、客户、竞争力、财务质量与增长 |
| 产业链 | 环节关系、价值分配、成本和供需传导、瓶颈、替代与情景 |

默认交框架方案、证据分配和缺口，不自动重排正文。已有确认框架时，新增内容先归入对应论点；重大变动先给具体方案。不能因为材料不全而硬凑机制或因果结论。

框架库通过多类报告逐步积累。新增框架卡可记录来源报告、适用问题、章节逻辑、证据要求、图表安排、局限和使用复盘；未经验证只列候选。

验收：M01 的真实路径、入口和边界可查；M02 的发现可回到来源、缺口具体；M05 的主线回答问题且有材料支持。只完成这些模块不声称已完成正文或正式底稿。
